# 单例模式学习笔记

## 核心概念

单例模式保证一个类在 JVM 中只有一个实例，并提供一个全局访问点。

可以概括为：

```text
构造方法私有化 + 类内部持有唯一实例 + 对外提供访问方法
```

## 饿汉式

对应代码：

```text
designpattern.singleton.SingletonEager
```

特点：

```text
类加载时直接创建实例
实现简单
线程安全
不支持懒加载
```

适合实例创建成本低、一定会被使用的场景。

## 双重检查锁

对应代码：

```text
designpattern.singleton.SingletonDoubleCheckLock
```

特点：

```text
懒加载
线程安全
第一次创建实例时才加锁
需要 volatile 防止指令重排序
```

双重检查的两次判断分别解决不同问题：

```text
第一次检查：实例已创建时，避免每次调用都加锁
第二次检查：多个线程等待锁后，避免重复创建实例
```

## 静态内部类

对应代码：

```text
designpattern.singleton.SingletonStaticInnerClass
```

特点：

```text
懒加载
线程安全
实现简洁
依赖 JVM 类加载机制保证只创建一次
```

外部类加载时不会创建实例，只有第一次调用 `getInstance()` 时，静态内部类才会被加载。

## 枚举单例

对应代码：

```text
designpattern.singleton.SingletonEnum
```

特点：

```text
线程安全
天然防反射破坏
天然防反序列化破坏
写法最简单
```

如果没有继承限制，枚举单例通常是生产代码中最稳妥的单例实现。

## 对比总结

| 实现方式 | 是否懒加载 | 是否线程安全 | 主要特点 |
| --- | --- | --- | --- |
| 饿汉式 | 否 | 是 | 简单，但实例提前创建 |
| 双重检查锁 | 是 | 是 | 灵活，但实现细节多 |
| 静态内部类 | 是 | 是 | 简洁，推荐学习掌握 |
| 枚举单例 | 否 | 是 | 最稳妥，防反射和反序列化 |
